## 2. 배경

파일럿 엑셀은 대시보드 모델을 만들기 위한 샘플이었다. 운영에서는 **보험사별 공시 재무제표(PDF)**가 원천이고,
앞으로 기간별·분기별로 갱신한다. 그래서 데이터 계층을 원문 → 추출 → 검증 → 통합 순서로 다시 짜는 중이다.
대사 규칙, 지표 정의, 템플릿, 한국어 버전, 배포는 그대로 쓴다.

## 4. 원문 전달 방식을 정한 경위

| 방식 | 결과 |
|---|---|
| 채팅 첨부 (클라우드 세션) | 첨부가 두 번 도착하지 않았고 크기 한도를 알 수 없음 |
| 원격 폴더 연결 (클라우드 세션 + Remote Control) | 공유한 4개 폴더 모두 "사용 불가"(앱 버전·폴더 위치·계정별 제공 여부 중 하나로 추정) |
| Google Drive 커넥터 (클라우드 세션) | 동작하지만 **실제 전송 한도가 약 5.5MB**. 6~10MB는 연결이 끊기고 10MB 초과는 거부됨. FY2025 17개 중 11개를 못 받음 |
| 큰 파일 분할 후 재업로드 | FWD로 시험해 성공했지만 파일마다 수작업이 필요해 채택하지 않음(3절 9번) |
| **로컬 세션 (채택)** | Mac에서 실행되므로 원문 폴더를 그대로 읽고 크기 제한이 없음 |

클라우드 세션은 태국 공시 사이트에 접속할 수 없었다. 로컬 세션은 Mac의 네트워크를 쓰지만, 결정 1에 따라 자동 수집은 범위 밖이다.

## 5. 로컬 세션 시작 절차

### 5-1. 사용자가 할 일 (처음 한 번)

1. 데스크톱 앱을 최신 버전으로 업데이트한다.
2. 저장소를 클론한다. iCloud Drive나 Google Drive 동기화 폴더 밖의 일반 폴더에 둔다(`.git`이 동기화와 충돌할 수 있음).
   ```bash
   mkdir -p ~/Documents/GitHub && cd ~/Documents/GitHub && git clone https://github.com/SeungraeKim81/IFRS17_Industry_Dashboard.git
   ```
3. 데스크톱 앱에서 **로컬** Claude Code 세션을 새로 열고, 작업 폴더로 `~/Documents/GitHub/IFRS17_Industry_Dashboard`를 지정한다.
4. 입력창 **+ → Add folder**로 원문 폴더 `FS_Life_Industry`를 추가한다.
   - Google Drive 앱으로 동기화되는 폴더면 보통 `~/Library/CloudStorage/GoogleDrive-<계정>/My Drive/FS_Life_Industry`에 있다.
   - 파일이 "온라인 전용"이면 읽을 때 내려받는다. 느리면 폴더를 우클릭해 오프라인 사용으로 설정한다.
5. 첫 요청 예시:
   > `docs/HANDOFF.md`를 읽고 6절대로 남은 10개사 추출을 시작해 줘. 원문은 추가한 `FS_Life_Industry` 폴더의 `Y2025/4Q_2025`에 있어. 새 브랜치에서 작업하고 PR은 내가 요청할 때만 열어 줘.

### 5-2. 로컬 세션이 할 준비 작업

1. 최신 `main`에서 작업 브랜치를 만든다(예: `extract-fy2025-remaining`).
2. 도구를 확인하고, 없으면 설치를 안내한다.
   - `python3 -m pip install -r requirements.txt pdfplumber pypdf pillow`
   - `brew install poppler` (`pdftotext`, `pdftoppm`, `pdfinfo`). Homebrew가 없으면 사용자에게 설치를 요청한다.
3. `python3 -m pipeline all`과 `python3 -m unittest discover -s tests`로 환경을 확인한다.
4. 원문 폴더에서 `Y2025/4Q_2025`의 파일 목록과 크기를 확인하고 7절의 등록부와 대조한다.
5. 커밋·푸시는 사용자의 GitHub 계정으로 한다. 푸시가 안 되면 `gh auth login` 또는 GitHub Desktop 로그인을 요청한다.

### 6-2. 회사 하나당 절차

1. **원문 확인**: `pdfinfo`로 쪽수를 보고, `pdftotext`로 텍스트가 있는지 확인한다. 등록부 행의 `sha256`, `pages`, `text_layer`를 채운다.
   `connector_download`에는 `n/a (read locally)`를 적는다.
2. **표 찾기**: 손익계산서, 보험수익·비용 분석, CSM 변동표(측정요소별), 신계약 표를 **제목으로** 찾는다.
   - 텍스트가 있으면 `pdftotext`로 제목을 검색한다.
   - 스캔본이면 `python3 tools/pdf_pages.py sheet <pdf> <시작> <끝> <out.png>`로 쪽 윗부분을 모아 보고 제목을 확인한다.
3. **추출 규격 작성** (`config/extraction/<보험사ID>.json`):
   - 텍스트 PDF: `samsung-life.json`처럼 `tables`(반드시 있을 문구 `all`, 없어야 할 문구 `none`, 앞 표 `after`)와 행 패턴으로 쓴다. 쪽 번호는 쓰지 않는다.
   - 스캔본: `python3 tools/pdf_pages.py page …`로 쪽을 보고 인쇄된 값을 그대로 옮겨 적는다(괄호는 음수, `-`는 0).
     `tools/visual_spec.py` 형식의 작은 파이썬 파일로 쓰고 JSON으로 변환한다. 쪽마다 확인한 제목을 `HEADINGS`에 적는다.
4. **추출·검증**:
   ```bash
   python3 -m pipeline extract --spec config/extraction/<id>.json --pdf "<원문 경로>"
   python3 -m pipeline verify-extract extract/2025FY/<id>.json
   ```
   - 대사 12/12가 아니면 원문을 다시 읽는다. 끝내 맞지 않으면 추정하지 않고 보고한다.
   - 파일럿과 다르면 원문 쪽으로 어느 쪽이 맞는지 판정해 기록한다(파일럿 쪽 오차도 있었음, 10절).
5. **마무리**: 등록부 `status`를 `extracted`로 바꾸고, `python3 -m pipeline review-workbook --period 2025FY`, `python3 -m pipeline all`, 테스트를 돌린 뒤 회사 단위로 커밋한다.
6. 10개사가 끝나면 10절 표에 결과를 더하고, 사용자에게 결과와 파일럿 대비 차이를 보고한다.

**작업량 참고**: 스캔본은 회사당 8~16쪽을 이미지로 읽는다(KTAXA처럼 합산하는 회사는 더 많음).
한 번에 한 회사씩 끝내고 커밋해야 작업 맥락이 넘치지 않는다.

## 7. 원문 보관과 등록부

- **원문**: Google Drive `FS_Life_Industry/Y<연도>/<분기>/`. 현재 `Y2025/1Q_2025 … 4Q_2025`, `Y2026/1Q2026, 2Q2026`. `4Q_<연도>`가 연차(FY)다.

  12 BUI, 14 PHILLIP, 16 SAHA는 파일럿 밖이었으나 FY2025는 추출했다(3절 11번).
  분기 파일 현황(2026-11-10 기준): 1Q_2025 19개, 2Q_2025 18개, 3Q_2025 19개, 1Q2026 20개, 2Q2026 20개, 모두 96개(1Q~3Q 2025에는 Rabbit, 2Q_2025에는 Phillip도 없음). 분기 공시 범위는 12절.
- **등록부**: `sources/<기간>/registry.csv`. 열은 company, period, doc_type, drive_folder, original_name, drive_file_id, bytes, sha256, pages, text_layer, connector_download, status.
  기간 표기는 `2025FY`, `2026Q1`, `2026Q2`(누적 6개월), `2026Q3`(누적 9개월).
- 원문 PDF·XLSX·DOCX는 커밋하지 않는다(`.gitignore`).
- **원문은 등록 후 바꾸지 않는다.** 정정 공시는 새 파일과 새 행으로 추가한다.
  추출 결과(`extract/`)에는 원문 지문이 들어가고, 테스트가 등록부와 대조한다. 조각 파일로 읽은 경우(FWD)는 조각마다 지문을 남긴다.

- 웹사이트(`_site/`)에는 원문이 올라가지 않는다.

## 8. 추출 시 주의점

- **표는 제목으로 찾는다.** AIA는 파일럿의 쪽 기록이 다른 판본 기준이었다(손익계산서 77쪽 대 7쪽, 17.1 146쪽 대 103쪽, 차이도 일정하지 않음).
  텍스트 PDF의 추출기는 조건에 맞는 쪽이 없거나 둘 이상이면 멈춘다. Samsung에서는 출재보험 CSM 변동표와 겹치는 것을 이렇게 잡았다.
- **단위**: 본문과 주석의 단위가 다를 수 있다(Samsung, Generali, T Life, Rabbit: 본문 바트, 주석 천 바트). AIA는 백만 바트, Dhipaya는 본문·주석 모두 바트.
  스캔본 규격에서는 `UNIT`을 기본값으로 두고 `UNITS = {쪽: 단위}`로 다른 쪽만 지정한다(`tools/visual_spec.py`).
- **부호**: 비용이 양수로 인쇄되면 뒤집는다(MTL, BLA, Thai Life, AIA). 법인세가 양수로 인쇄되는 회사도 있다(BLA, AIA, Southeast).
  FWD는 CSM·신계약 표 전체가 반대 부호로 인쇄돼 있다. Thai Life·MTL·BLA는 주석의 수익·비용 표만 양수이고 손익계산서는 음수다.
  Generali는 법인세 줄이 '비용(수익)'이라 괄호 값이 수익(+)이다(세전이익 + 괄호 값 = 순이익으로 확인).
- **합산**: KTAXA 상품군 4개(9~12), Dhipaya 포트폴리오 2개(9.x + 10.x), BLA GMM(7.1) + VFA(7.3). Samsung은 상품별 표와 합계(ทั้งหมด) 표가 함께 있어 합계를 쓴다.
  합산 항목은 첫 번째 표의 쪽을 기록하고 `HEADINGS`에 나머지 표의 쪽을 적는다.
- **연결·지분법 열**: Thai Life(지분법), Muang Thai(지분법), Bangkok Life(연결)는 손익계산서에 열이 두 벌 있다. 별도 재무제표 열을 쓴다(3절 10번).
- **머리글 함정**: Southeast는 비교기간 쪽에도 당기 머리글('สำหรับปีสิ้นสุดวันที่ 31 ธันวาคม 2568')이 찍혀 있다. 연도는 표 자체의 열 머리글로 정하고 기초 잔액으로 확인한다.
- **법인세 줄 이름과 괄호**: 줄 이름이 '비용(수익)'이어도 괄호가 비용인 회사(Saha)와 수익인 회사(Generali)가 있다. 매번 세전이익 → 순이익 다리로 확인한다.
  BUI는 손익계산서의 비용을 괄호 없이 양수로 인쇄하고, 법인세 줄은 '수익(비용)'이라 괄호가 비용이다.
- **신계약 표의 부호와 분해**: Saha는 미래 현금유입을 괄호 없이 인쇄한다(부호 그대로). BUI는 유출을 합계로만 인쇄한다(3절 12번).
- **별도 재무제표 안의 지분법**: Phillip의 별도 재무제표는 종속회사를 지분법으로 처리한다. 그 손익은 기타수익에 넣는다(Thai Life 관계회사와 같은 처리).
- **신계약 표의 손실부담 열**: T Life FY2025, Southeast, Phillip FY2025는 손실부담이 아닌 열에도 부채 증가액이 있거나(240, 401), 손실 전체가 다른 열에 있다(Southeast FY2024). 합계 열은 대사가 맞으므로 합계를 쓰고 규격에 기록한다.
- **미래서비스 CSM 변동** = 추정 변경 + 손실부담계약 행(CSM 열에 값이 있을 때) + 경험조정. 신계약은 따로 잡는다.
- **이자부리**는 보험금융 행 중 당기손익 부분(CSM 열)이다. VFA 그룹은 `-`일 수 있다(KTAXA 12).
- **기타비용** = 기타 금융원가 + 기타 영업비용. 보험취득현금흐름 손상이 따로 있으면 상각에 더한다(Allianz).
- **RA 해제**는 보험수익 주석의 값(LRC 기준)을 쓴다. AOC의 RA는 LRC+LIC라 다르다(Samsung, Prudential).
- **재무제표 자체의 차이**: AIA FY2024 CSM 상각은 17.1이 12,270, 17.3이 12,271이다. 17.1을 쓰고 1백만 차이는 미래서비스 변동에 반영했다(근거를 규격에 기록).
- **가로 방향 쪽**: Tokio 26.1, AIA 17.3, Allianz 30.1은 옆으로 인쇄돼 있다. `--rotate 90` 또는 `-90`으로 돌려 본다. 거꾸로 보이면 반대로 돌린다.
- **주석 구성은 해마다 바뀔 수 있다**: Tokio는 FY2025에 보험수익·비용 분석 주석 26.1이 생겨, 파일럿처럼 계산으로 구할 필요가 없어졌다.
- **OCR은 쓰지 않는다**: 태국어 Tesseract는 300dpi에서 쪽당 약 2분이라 비현실적이다. 필요한 쪽만 이미지로 읽는다.
- **확인 못 한 값은 추정하지 않는다.** 비워 두고 사유를 기록한다.
